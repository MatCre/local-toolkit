01 · The big picture

One AI layer, five tools on top

Every tool talks to IChatClient, an interface from Microsoft.Extensions.AI. None of them knows whether Claude, OpenAI or Ollama answers. That's what lets a tool keep working with Wi-Fi off or once the monthly budget runs out.

02 · The request pipeline

What happens to a prompt

The AI layer is a chain of clients, each wrapping the next, like ASP.NET Core middleware. A layer can inspect the request, change it, answer it without calling further in (a cache hit), or pass it inward and act on the response coming back. You build the chain in one place, ServiceCollectionExtensions.cs, with AddChatClient(inner).UseXxx().

BuiltRuns on your machinePlanned
Your code: Sandbox / Vault / Cards …caller Asks DI for IChatClient and calls GetStreamingResponseAsync(prompt).
LoggingChatClientSession 1 From .UseLogging(). Writes "invoked" and "completed" at Debug level. That's the dbug: lines you see in the console.
VaultLoggingChatClientSession 5 Saves each prompt and answer into the vault's SQLite store.
DistributedCachingChatClientSession 3 From .UseDistributedCache(). A repeat prompt returns the stored answer and never goes further in.
BudgetChatClientSession 3 Sums this month's logged cost and takes cloud providers out of the running past your cap.
RoutingChatClientSession 2 Tries providers in order from appsettings.json and moves to the next on failure. Logs provider, tokens and cost.
OllamaApiClientSession 1 From OllamaSharp. Turns the ChatMessage list into Ollama's JSON and streams the reply back as ChatResponseUpdate chunks.
process boundary · HTTP POST localhost:11434/api/chat
Ollama server → qwen2.5-coder:7blocal Loads the model into GPU memory on first use and keeps it there about 5 minutes after the last call. Tokens stream back as newline-delimited JSON.

Why this order? Logging sits outermost so it sees every call, including cache hits. The cache sits outside the budget check so a cached answer costs nothing and isn't counted. The router is innermost of the custom layers because it's the one that picks a vendor.

03 · Startup sequence

From dotnet run to the first token

  1. SDK selection. The dotnet muxer reads global.json, which asks for 11.0.100, and finds that SDK. The dotnetup install has it; C:\Program Files\dotnet doesn't (see the PATH note below).
  2. Build. MSBuild applies Directory.Build.props (net11.0, nullable, warnings as errors) and Directory.Packages.props (one version per NuGet package) to every project, then compiles Toolkit.AI and Sandbox.
  3. Host builder. Host.CreateApplicationBuilder sets up configuration, logging and a DI container: the same plumbing ASP.NET Core and Worker Services use.
  4. Configuration loads in layers. The table below shows the order. Later sources override earlier ones key by key.
  5. Registration. AddToolkitAI(config) binds the ToolkitAI section to ToolkitAIOptions, registers validation, and registers a factory for the IChatClient pipeline. Nothing is constructed yet.
  6. Build the container. builder.Build() freezes the registrations.
  7. Resolve. GetRequiredService<IChatClient>() runs the factory: it reads the options, which triggers validation, creates OllamaApiClient, then wraps it in LoggingChatClient.
  8. Call. await foreach over GetStreamingResponseAsync prints each chunk as it arrives. The final chunk carries a UsageContent with token counts.

The ToolkitAI:Ollama:Model key in JSON, ToolkitAI__Ollama__Model as an environment variable, and the Model property on OllamaOptions are the same setting. The binder maps one to the other by name.

05 · Repository

How the repo is organised

local-toolkit/
├─ global.json                 SDK pin
├─ Directory.Build.props       shared MSBuild settings
├─ Directory.Packages.props    all NuGet versions
├─ LocalToolkit.slnx           solution (XML format)
├─ docs/architecture.html      this page
├─ src/
│  ├─ Toolkit.AI/              class library
│  │  ├─ ToolkitAIOptions.cs
│  │  └─ ServiceCollectionExtensions.cs
│  └─ Sandbox/                 console app
│     ├─ Program.cs
│     └─ appsettings.json
└─ tests/
   └─ Toolkit.AI.Tests/        xUnit
      └─ AddToolkitAITests.cs
Toolkit.AI is a library, not an app. It has no Main and no config files of its own. The app that uses it supplies configuration.
Sandbox is a scratch app for trying the layer by hand. Later tools are separate apps that reference Toolkit.AI the same way.
Tests check the wiring without calling Ollama, so they pass offline and in CI. They prove options bind, the pipeline order is right, and bad config fails fast.
Project references point one way: Sandbox → Toolkit.AI ← Tests. Toolkit.AI never references an app.
.slnx is the XML solution format, the default since the .NET 10 SDK. It's readable and merges cleanly in Git.

PATH note: two dotnet installs

C:\Program Files\dotnet (SDKs 8 and 10) comes before the dotnetup install (which also has 11.0.100) on PATH, so a plain dotnet picks the old one and fails in this repo with an SDK-not-found error. To fix it, move %LOCALAPPDATA%\dotnetup\dotnet above C:\Program Files\dotnet in your user PATH, or point your IDE's .NET path at the dotnetup folder.

07 · Glossary

Terms used in the code

IChatClient
The vendor-neutral chat interface in Microsoft.Extensions.AI. It has two methods, one for a whole response and one for a stream.
ChatClientBuilder
What AddChatClient returns. Each .UseXxx() adds a wrapping layer, and the last one added becomes the outermost.
DelegatingChatClient
The base class for writing your own layer (Router, Budget, VaultLogging). You override the two methods and call base to pass the request inward.
GetService<T>()
Walks down the pipeline to find a layer of type T. The tests use it to confirm Ollama is innermost.
Options pattern
Binds a config section to a class (IOptions<ToolkitAIOptions>). ValidateOnStart makes bad config fail when the app starts instead of on first use.
Central Package Management
Directory.Packages.props holds every package version. A .csproj lists package names only.
Generic Host
Host.CreateApplicationBuilder: configuration, logging and DI in one object. Workers (S9) and Blazor apps (S5, S13) use the same model.
